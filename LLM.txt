# PolyBlocks | No‑Code Polymarket Strategy Builder

> A comprehensive no-code platform for building, backtesting, paper trading, and automating Polymarket trading strategies using visual blocks and AI assistance.

PolyBlocks provides a visual, no-code environment for traders to develop complex strategies on Polymarket. It integrates real-time data, AI-powered strategy generation, and automated execution, enabling both beginners and advanced users to trade smarter without programming knowledge.

## Core Content

### Strategy Building and Automation
- Drag-and-drop strategy builder
- Visual canvas with animated data-flow
- AI-driven strategy creation from plain English prompts (Gemini 2.5 Flash)
- Connect logic, triggers, conditions, and actions visually
- Automate strategies for 24/7 trading
- Backtest and paper trade safely before live execution
- Live trading via CLOB API integration

### Block Types and Functionalities
- 31+ block types including:
  - **Trigger Blocks**: Interval, Price Cross, Manual, Event Resolution
  - **Market Blocks**: Market Selector, Recent Crypto Market, User Activity (copy trading)
  - **Data Blocks**: Price Data, Spread Data, Orderbook, Price History, Multi-Market Compare, Custom API
  - **Logic Blocks**: AND/OR/NOT Gates, IF/ELSE, Threshold Compare, Cooldown, Math Operations
  - **Risk Blocks**: Max Exposure, Daily Loss Limit, Kill Switch
  - **Action Blocks**: Place Order, Limit Order, Cancel Order, Close Position, Notification
  - **Analysis Blocks**: Position Sizer (Kelly), Probability Calc, Expected Value, Edge Calc
  - **Utility Blocks**: Debug Log, Delay, Note
- External API integration for custom data sources (weather, crypto, news, etc.)
- Advanced logic systems for multi-market comparison and complex decision trees

### Trading Features
- Paper trading with realistic simulation
- Real order execution on Polymarket via CLOB API
- Copy trading from top wallets with duplicate prevention
- Portfolio monitoring and position tracking with live PnL
- Auto-execution with full wallet control
- Rate-limited AI strategy generation (30 requests/day/user)

### Frontend

- React Flow for visual node-based editor

- Vite for build tooling

### Backend
- Fastify 5.x REST API

### AI Integration
- Google Vertex AI with Gemini 2.5 Flash

### APIs Integrated

- **Google Vertex AI**: AI strategy generation

- Node.js 22.x
- pnpm 9.15.0

## Authentication & Security

### Session-Based Auth
- MongoDB sessions collection
- Session tokens via `x-session-token` header
- Token validation with `resolveSession()` helper
- All protected routes require valid session

### Paper Trades Isolation
- Server-side userId validation (never trust frontend)
- `requireAuth()` helper extracts userId from session
- All queries filtered by `{ userId, strategyId }`
- Returns 401 if not authenticated

### Rate Limiting
- AI: 30 requests per day per user
- Tracked in MongoDB `ai_usage` collection
- Automatic reset at midnight UTC
- Headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`

## Common Issues

### "Paper trades appearing in wrong account"
- Ensure session token is sent in `x-session-token` header
- Check browser console for 401 errors
- Verify user is logged in (not "anonymous")
- Server validates userId from session, ignores frontend userId

### "AI generation fails"
- Check `VERTEX_AI_KEY` is valid service account JSON or access token
- Verify `VERTEX_AI_PROJECT_ID` matches your GCP project
- Check rate limit (30/day/user)
- Review Heroku logs: `heroku logs --tail`

### "Strategy won't start"
- Check validation errors (shown in red banner at top of editor)
- Ensure at least one trigger block is present
- Verify market selector has a market chosen
- Check for disconnected required inputs

### "Build fails on Heroku"
- Ensure pnpm-lock.yaml is up to date
- Run `pnpm install` locally and commit lockfile
- Check TypeScript errors: `pnpm build` locally first

## Contributing

### Code Style
- TypeScript with strict mode
- Explicit types for function parameters and returns
- Use `type` for unions, `interface` for object shapes
- Avoid `any` — use `unknown` when needed
- ES modules with `.js` extensions in imports

### Naming Conventions
| Element | Convention | Example |
|---------|------------|---------|
| Files | kebab-case | `marketplace.test.ts` |
| Functions | camelCase | `getUserId` |
| Types | PascalCase | `EditorState` |
| Constants | SCREAMING_SNAKE_CASE | `CLOB_HOST` |
| Components | PascalCase | `<EditorCanvas />` |

### Commit Messages
- Focus on "why" not "what"
- Concise (1-2 sentences)
- Present tense: "Add feature" not "Added feature"
